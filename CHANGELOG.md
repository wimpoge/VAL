### Day 4 — Prompt Engineering Advanced (N16–N20)

- **Backend `routers/day04.py` — five endpoints**, single-language per the 2026-05-11 policy (the roadmap's original bilingual `{response_en, response_id}` shape is frozen as spec, not implementation). Shared `_usage()` / `_fail()` helpers; every model call is `track()`-ed under `day="day04"`.
  - `POST /structured` — body `{description, provider?}`. System prompt declares a fixed six-key schema (`name, category, price_range ∈ budget|mid|premium|unknown, sentiment ∈ positive|negative|neutral, key_features[2–5], summary`) with `response_format={"type":"json_object"}`. Validates/normalizes enum fields server-side, clamps `key_features` to 5, returns parsed object + the `raw` JSON string + tokens.
  - `POST /system` — body `{question, provider?}`. Runs the **same user question** through three system-prompt variants (`none` baseline / `concise` terse-expert / `eli5`) and returns `results[]` of `{id, label, system, note, answer, tokens}` so the UI can diff behavior at fixed input.
  - `POST /role` — body `{task, role, provider?}`. `role` is a `ROLE_PRESETS` key (`security_engineer` / `kindergarten_teacher` / `unix_manpage`) or free-text. Makes two calls — plain (no system) vs roled (role as system) — returns `{plain, roled, role_system, …}`.
  - `POST /react` — body `{question, provider?}`. Classic text-format ReAct loop (not the tool-calling API): system prompt constrains output to `Thought:` / `Action:` / `Action Input:` or `Final Answer:`. Up to 6 iterations with `stop=["Observation:"]`; `_parse_react()` line-scans each step, the server executes `calculator` (AST allow-list eval, same `_safe_arith` as Day 3) or `lookup` (small `_FACTS` table with fuzzy contains + first-principles fallback), appends `Observation:` and re-prompts. Returns an ordered `steps[]` of `{type: thought|action|observation|answer, …}` plus `answer`, `iterations`, summed tokens.
  - `POST /temperature` — body `{prompt, temperatures[], provider?}`. One call per temperature (clamped to `[0,2]`), returns `results[]` of `{temperature, response, tokens}`.
- **Frontend `app/day-04/page.tsx` — five node tabs N16–N20**, same shell as Day 3 (header + day-progress chip, `NODES` nav with ✓, mark-complete wired to `useNodeProgress(4)`, `lg:-mx-24 xl:-mx-40` widening). Local helpers `SectionHeader` / `ErrorBox` / `Footer` / `ExplainerBlock` / `ProviderRow` / `PresetRow` / `SubmitButton` / `Badge`; shared `VIZ` palette (`green #1D9E75, blue #378ADD, violet #7F77DD, amber #FAC775, coral #F5C4B3`).
  - **N16 Structured** — 2-col "Unstructured input → Structured output". Each schema key renders as a colored left-border block; `key_features` as `Badge` chips, `sentiment` as a color-coded badge (green/red/grey).
  - **N17 System** — an "identical user message" callout pinned above a 3-col grid; each column shows the variant label, its system prompt in a mono box (`— (none)` for the baseline), the answer, and per-call tokens. Loading state renders 3 placeholder columns.
  - **N18 Role** — role-preset pills (violet active state) + task presets; the resolved `role_system` shown in a violet-left-border strip; 2-col `RoleColumn` "No role" (grey) vs "With role" (violet).
  - **N19 ReAct** — tool palette badges (calculator/lookup), then an `<ol>` of step nodes colored by type (thought violet / action blue with tool chip + mono input / observation amber / answer green 1.5px bold). Refs-only staggered reveal: `stepRefs[]` flipped via `setTimeout` (120ms + i·280ms) pushed into `timersRef`, kicked off in `requestAnimationFrame` after the response; cleanup clears timers on unmount.
  - **N20 Temperature** — a blue→amber→coral gradient spectrum bar with `0.0 focused / 0.7 balanced / 1.4 wild` labels, then a 3-col grid of per-temperature cards (top-border tinted by temp band) with response + tokens; placeholder cards while sampling.
  - Every node closes with an `ExplainerBlock` articulating the underlying mechanic (schema-as-contract, system prompt as leverage, role as behavior switch, reason→act→observe loop, temperature as the creativity dial).

### Navbar — responsive on mobile with a days hamburger menu

- The sticky-header day nav had `hidden md:flex`, so on screens < 768 px the 10 day links disappeared entirely. Mobile users had no way to switch days from the navbar.
- **Final shape on mobile (< sm).** `● VAL  [☰]                  [76,680 tok · $0.0223]`. The hamburger sits in the left group right after the `VAL` wordmark (the natural primary-nav slot). Tapping it opens a panel beneath the sticky header with two sections:
  - **Days** — `grid-cols-5 gap-1.5` so the 10 day chips lay out as 2 rows of 5. Same active/done coloring as the inline chips: active+done = filled accent; active+not-done = filled foreground; not-active+done = accent outline with `✓`.
  - **More** (separated by a top border) — stacked `Usage` and `Advanced` links matching the desktop chip styling.
  - Tapping any link calls `setMenuOpen(false)`; a route change also auto-closes via the existing `useEffect` on `pathname`.
- **On `sm+`** the inline day nav comes back (`hidden ... sm:flex` on the `<nav>`) and `Usage` / `Advanced` re-appear inline in the right group (`hidden ... sm:inline-block`). The hamburger button itself is `sm:hidden` so it disappears on desktop.
- **Layout knobs that made everything fit.** Outer flex container went from `gap-6 px-6` to `gap-3 px-3 sm:gap-6 sm:px-6` to recover mobile horizontal room. Left wrapper got `min-w-0 flex-1` so its inline day nav (on `sm+`) can `overflow-x-auto` without pushing the right group off-screen; scrollbar hidden via `style={{ scrollbarWidth: 'none' }}`. VAL link, hamburger, and each day chip all carry `shrink-0` so nothing collapses to illegibility.
- **Iterations along the way.** First attempt removed the `hidden md:flex` outright and relied on horizontal scroll — visible but only ~2 days fit before the right-side controls. Second attempt tried a hamburger that contained `Usage` + `Advanced`; corrected after feedback so the hamburger holds days instead. The hamburger was initially grouped with the right-side controls, then moved to sit immediately after `VAL`. Next fix: `Usage` + `Advanced` were still inline on mobile and overlapping the hamburger because the right group couldn't fit at < 380 px — moved them into the hamburger panel's new "More" section, so the mobile inline navbar shrinks to just `VAL + ☰ + token button`.
- **Scroll trap fix.** With the panel sitting inside `sticky top-0`, an opened menu would extend the sticky height and on short viewports (landscape phone) effectively own the visible area — the user reported that page scroll wouldn't engage until they had scrolled the menu content to its end. Two changes resolved it: (a) the panel's inner container got `max-h-[calc(100vh-3.5rem)] overflow-y-auto overscroll-contain` so it's bounded by viewport-minus-header and won't chain-scroll the page, and (b) a `useEffect` (gated on `menuOpen`) attaches `mousedown` + `touchstart` listeners on `document` that close the menu when the target is outside both `menuRef` (the panel) and `menuButtonRef` (the hamburger). Listeners are cleaned up when the menu closes or the component unmounts. Result: any tap on the page area dismisses the menu and the user can scroll immediately; taps inside the menu (including the day chips and Usage / Advanced links, which already had `onClick={() => setMenuOpen(false)}`) keep working as before.

- **One-click launcher.** Added `start-all.bat` + `start-all.ps1` at the repo root. The `.bat` is a thin shim — double-click from Explorer and it runs the `.ps1` with `-ExecutionPolicy Bypass -NoProfile`. The PowerShell script does four sequential phases: (1) probes `docker info` and, if the daemon isn't up, launches Docker Desktop from `$env:ProgramFiles\Docker\Desktop\Docker Desktop.exe` and polls every 2 s for up to 2 minutes until it's ready, printing dots while waiting; (2) `docker inspect`-checks the `ai-roadmap-pg` container — if missing, prints the canonical `docker run …` command with the `ai-roadmap-pg-data` volume + `pgvector/pgvector:pg16` image and exits; if stopped, runs `docker start`; (3) spawns a new PowerShell window for the backend (`uvicorn main:app --reload --port 8000`) with auto-detection of `backend\.venv\`, `backend\venv\`, or `backend\env\` activate scripts; (4) spawns another window for the frontend (`npm run dev`). - **UTF-8 mojibake purge in `day-01/page.tsx`.** Browser was rendering tabs as `ÅŒ N1 AI ENGINEER` and the submit button as `ASK Â†'` — every special character mangled. Root cause: at some point the file went through a UTF-8 → cp1252 → UTF-8 round-trip and the literal multi-byte glyphs got stored as their cp1252 misreading, then re-encoded as UTF-8. The file was still valid UTF-8 but its content was no longer the characters intended (`→` U+2192 stored as the 8-byte sequence `C3 A2 E2 80 A0 E2 80 99`, which decodes as `â†'`; CSS `uppercase` on the button then made `â` into `Â`). Diagnosed via a Python byte-level scan of all `.tsx`/`.ts`/`.css` under `app/` looking for the `C3 A2 E2|C2|C5` triple-byte mojibake prefix — only `day-01/page.tsx` was affected, with 11 sequences across 7 distinct corrupted glyphs: `✓`×2, `→`×1, `…`×4, `–`×1, `○`×1, `▾`×1, `▸`×1. Fixed via byte-level `data.replace(mojibake_bytes, real_utf8_bytes)` for each pattern, written back in binary mode so no editor / shell re-encoding could re-corrupt them. - **Token counter persists across backend restarts.** `_totals` in `backend/token_tracker.py` was in-memory only, so any uvicorn `--reload` (or full backend restart) zeroed the navbar counter even though every call had been written to Postgres `token_usage` via `_persist`. Root cause: the bars container was `flex h-44 items-end` — `items-end` aligns children to the bottom of the cross axis but doesn't stretch them.
